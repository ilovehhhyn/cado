# Integrity monitor validation

@generated by scripts/integrity_validation.py. Do not edit by hand.

Method: 50 seeds per row. The synthetic batched runs come from `tests/support.py` (`batched_series`: 8 prompts x 4 rollouts per step, prompt difficulty drawn around a pass rate that rises 0.1 over the run, so rollouts of one prompt are correlated; `mismatch_series`). Default `IntegrityOptions`: alarm_probability 0.999, hazard 0.001 per step, failure rates 0.02/0.16 with an estimated Rao-Scott design effect, reward reference 20 steps lagged 10, shift 0.25 unit sd, kl 0.001/0.01, ratio shift 0.01. Delay is counted in steps from the first changed step (150). A miss is no alarm before the run ends.

These generators match the detector's assumptions except for the correlation and drift they add on purpose; they show the detector works as designed, not how it performs on a real run.
